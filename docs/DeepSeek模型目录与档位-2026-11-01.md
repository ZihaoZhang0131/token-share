核对日期：2026-11-01。站点：`https://tokenshare.asia`。沿用管理员已保存的 Deepseek 上游及加密 Key。

## 当前模型与公开入口

官方现行目录和该 Key 的 `/models` 列表均包含两个模型：

| 上游模型 ID | 官方当前版本 | 本站公开入口 |
|---|---|---|
| `deepseek-flash` | DeepSeek-V4.1-Flash-1017 | 基础名，以及 `-none`、`-low`、`-high`、`-max` |
| `deepseek-v4-pro` | DeepSeek-V4-Pro-0813 | 基础名，以及 `-none`、`-low`、`-high`、`-max` |

共 10 条 DeepSeek 路由，本次新增 9 条，原有 Pro 基础入口保留并开启 Responses。与已有 54 条 OpenAI 路由合计 64 条。管理员刷新“模型”即可查看。

旧名称 `deepseek-v4-flash` 和 `deepseek-v4-flash-vision-exp` 目前是 Flash 的兼容入口，不作为新的独立模型重复添加。依据：[官方模型目录](https://api-docs.deepseek.com/quick_start/pricing/)、[官方更新记录](https://api-docs.deepseek.com/updates/)。

## 档位与接口

10 个入口均支持聊天 `/v1/chat/completions` 和编码 `/v1/responses`。DeepSeek 的 max 可用于两种接口，不沿用 OpenAI 的 max 仅 Responses 限制。

- `none`：关闭思考。Chat 转为 `thinking.type=disabled`，不把 `reasoning_effort=none` 直接转发；Responses 使用 `reasoning.effort=none`。
- `low / high / max`：Chat 注入 `thinking.type=enabled` 和对应 `reasoning_effort`；Responses 注入对应 `reasoning.effort`。
- 基础入口不固定档位，未指定时保留上游默认思考模式和 high 档位。
- 固定别名不允许覆盖强度，也不能用相反的 thinking 开关绕过。

官方会将 minimal 映射 low、medium/xhigh 映射 high、ultra 映射 max。本站只配置实际档位，不增加名称不同但实际相同的入口；请求未配置的强度时返回 422，提示使用 none/low/high/max。依据：[官方思考模式说明](https://api-docs.deepseek.com/guides/thinking_mode/)。

编码使用无状态 Responses，历史和工具输出由客户端显式传回。支持 function 和名为 apply_patch 的 custom 工具；不开放上游托管搜索、文件和其他私有资源。DeepSeek 返回明文 reasoning 项，不能套用 OpenAI 加密 reasoning 的假设，工具续接应保留完整 output。依据：[官方 Responses 兼容说明](https://api-docs.deepseek.com/guides/responses_api/)。

思考模式的工具选择使用 `auto` 或 `none`；`required` 和指定工具名只用于 none 档位。两个接口实测均有此限制，中转站会提前返回 422 提示，不自动关闭思考或更改客户端意图。

## 额度与授权

新入口最大输出统一为 16,384 Token；原有 `deepseek-v4-pro` 保持管理员设置的 100,000，不覆盖已有额度配置。Chat 的 `max_completion_tokens` 自动转为 DeepSeek 的 `max_tokens`；仍不能同时传两个上限。

用户白名单、密码、月额度和 Key 限速不变。需要使用新增别名的用户，由管理员在“用户 → 编辑”中单独分配；已有 Pro 使用者仍可用原来的模型名。

```python
from openai import OpenAI

client = OpenAI(
    base_url="https://tokenshare.asia/v1",
    api_key="你的中转站Key",
    max_retries=0,
)

chat = client.chat.completions.create(
    model="deepseek-flash-none",
    messages=[{"role": "user", "content": "解释 Python 生成器。"}],
    max_completion_tokens=2048,
)

response = client.responses.create(
    model="deepseek-v4-pro-max",
    input="检查这个函数的边界情况：def add(a, b): return a + b",
    max_output_tokens=4096,
    store=False,
)
```

## 配置维护与回退

`scripts/configure_deepseek_models.py` 默认只预览，显式 `--apply` 才写入。它核对官方上游、账号可见模型及别名冲突，事务提交并写审计，保留已有输出上限、不修改用户授权。重复运行不重复创建；不匹配的同名路由会使事务回滚。

```sh
docker compose exec -T api python - --provider-id UUID < scripts/configure_deepseek_models.py
docker compose exec -T api python - --provider-id UUID --apply < scripts/configure_deepseek_models.py
```

本次部署前备份：`/root/token-station-releases/20261101-deepseek-catalog/`；旧镜像：`token-station-api:before-deepseek-catalog`。回退优先停用新别名、把原 Pro 改回 chat 并恢复策略代码。不要直接覆盖全库，否则可能丢失备份后的用量和管理员操作。
