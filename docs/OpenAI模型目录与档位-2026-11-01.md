## 接口差异：max 不是双模式

本次对 8 个模型的真实上游分别发送 Chat Completions `reasoning_effort=max`，均返回 HTTP 400 / `unsupported_value`。因此按实际接口能力配置：

- 46 个基础入口和非 max 档位入口：聊天 + 编码。
- 8 个 `-max` 入口：仅编码，即 `/v1/responses`。
- Chat 请求指定 max：中转站在访问上游和预留额度前返回 422，不降级、不重试。
- 固定档位不允许客户端覆盖，例如 `gpt-6-astra-low` 不能传入 `reasoning.effort=max`。

官方模型页列出模型总体支持的强度，不等于每个接口都接受全部强度；本目录同时采用官方能力说明和当前账号的实测结果。

工具调用遵循 [官方 GPT‑6 接口兼容说明](https://developers.openai.com/api/docs/guides/latest-model)：Astra、6.1 Sol、6.1 Terra 需要 Responses；6 Sol 和 6 Luna 的 Chat 工具调用仅允许 none 档位。编码统一推荐 Responses，由客户端执行 function/custom 工具，中转服务器不执行命令。GPT‑6 推理开启时拒绝 temperature、top_p、logprobs 等不兼容参数。

## 额度与使用方式

全部 OpenAI 入口保留 16,384 的单次最大输出上限，包含推理 Token。它是本站安全上限，不是模型官方上下文长度。账号月额度、Key 的 RPM/TPM 继续生效。

管理员在“模型”页刷新即可查看。普通用户的模型白名单没有自动扩权；需要管理员在“用户 → 编辑”中单独分配所需公开别名，再由该用户用自己的中转 Key 调用。

```python
from openai import OpenAI

client = OpenAI(base_url="https://tokenshare.asia/v1", api_key="你的中转站Key", max_retries=0)

# 普通聊天：强度已由别名固定，不需要重复传 reasoning_effort。
chat = client.chat.completions.create(
    model="gpt-5.6-terra-high",
    messages=[{"role": "user", "content": "解释一下 Python 生成器。"}],
    max_completion_tokens=2048,
)

# max 使用 Responses；编码工具的完整用法见聊天与编码模式接入指南。
response = client.responses.create(
    model="gpt-6-astra-max",
    input="检查这段函数的边界情况：def add(a, b): return a + b",
    max_output_tokens=2048,
    store=False,
)
```

强度更高不代表所有任务都更好，也可能增加耗时和费用。配置没有包含 Pro mode、托管工具、多 Agent 或 WebSocket 功能。

## 可重复配置与回退

`app/model_policy.py` 保存明确的能力矩阵；`scripts/configure_openai_models.py` 默认只预览，显式 `--apply` 才写数据库。脚本验证官方上游地址、账号可见模型、别名冲突，按事务新增并记录审计，不更换上游 Key，不修改用户授权、密码和额度。重复执行不会重复新增；已存在但不匹配的路由会中止整个事务。唯一自动纠正是将同模型、同档位的 max 双模式路由改为 Responses。

在服务器项目目录运行（用管理台对应的 Provider ID 替换 UUID）：

```sh
docker compose exec -T api python - --provider-id UUID < scripts/configure_openai_models.py
docker compose exec -T api python - --provider-id UUID --apply < scripts/configure_openai_models.py
```

本次备份目录为 `/root/token-station-releases/20261101-model-catalog/`，包含变更前数据库、源代码和参数策略文件；旧 API 镜像标签为 `token-station-api:before-model-catalog`。回退优先停用本次新增别名并恢复策略代码，不要直接覆盖整个在线数据库，否则会丢失备份后的用量和管理员操作。
