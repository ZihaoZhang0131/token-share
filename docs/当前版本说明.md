## 页面与行为

| 场景 | 当前实现 |
|---|---|
| 未登录 | `Login.tsx` 渲染访客版 `UserConsole`，用量显示 `—`，身份相关动作触发登录弹窗 |
| 首次登录 | `PasswordGate` 要求修改临时密码 |
| 管理员 | 总览、上游、模型、用户、调用日志、审计日志 |
| 普通用户 | 用量、访问 Key、接入指南 |
| Key 创建 | 明文仅创建成功时在弹窗中展示，关闭后不再读取 |
| 移动端 | CSS 断点调整导航、布局、表格和弹窗 |

访客界面不代表放开权限。后端仍通过 Session、角色、CSRF 和 Bearer Key 验证控制实际读写权限。

## 代码和设计文件各自负责什么

- `frontend/src/main.tsx` 是唯一前端入口，加载 `App.tsx` 和 `styles.css`。
- `App.tsx` 负责 Session 恢复、改密状态和角色分流。
- `Login.tsx`、`AdminConsole.tsx`、`UserConsole.tsx` 是实际运行的页面。
- `components.tsx` 提供弹窗、按钮、表单与用量条等共享组件。
- `styles.css` 包含基础布局与后续 Open Ledger 覆盖规则，两部分共同决定最终样式，不能只复制末尾主题段。
- `DESIGN.md`、`PRODUCT.md` 是设计与产品约束。
- `.impeccable/` 保存设计过程、备选图和历史检查截图，属于参考资料，不是另一个可运行的前端；历史截图不等于当前页面验收。
- `.agents/skills/` 是项目内开发辅助资料，不作为前端入口或后端运行模块。
- `frontend/dist/` 是本地构建产物；生产通过 `frontend/Dockerfile` 重新构建，不提交到 Git。

本轮保持既有 UI 和 API 行为，更新了架构文档中仍描述“未做审计页”“独立登录页”的旧内容，并清理了已删除的学习文档草稿标记。

## 验证与发布边界

本轮执行后端 Pytest、Ruff、前端类型检查、生产构建，并使用临时数据库检查浏览器流程。测试不使用线上账号或真实上游 Key。

仓库现有自动化测试主要覆盖认证、上游加密、普通/SSE 代理和归档。它不等于全量生产压测或真实供应商验收。

此次交付是 GitHub `main` 代码同步。推送不会自动部署阿里云，线上更新仍应遵循 [日常迭代与线上发布指南](日常迭代与线上发布指南.md)。

已知独立运维事项仍保留在架构文档中，例如首次 TLS 脚本的环境变量优先级、备份管道错误检查；此次 UI 版本整理不表示这些事项已修复。
