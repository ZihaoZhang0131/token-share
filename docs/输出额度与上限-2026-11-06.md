# 输出额度与模型允许上限

## 规则

- `max_output_tokens`：模型路由允许的硬上限；现有官方 OpenAI 入口为 128,000，DeepSeek 为 393,216。
- `default_output_tokens`：默认输出额度；正整数表示管理员固定值，`null` 表示自动。固定默认值必须不大于允许上限。
- 客户端明确传入额度时优先使用，超过允许上限返回 422，不静默截小。
- 客户端省略额度时才选择默认值。自动默认不会超过路由允许上限。
- TPM 和月额度按 **估算输入 + 本次采用的输出额度** 预留，并向上游发送相同额度。收到 usage 后按实际输入和输出结算；无 usage 时保守按该预留结算。
- 输出额度包含推理和回答，不是上下文窗口。提高允许上限不代表每次都生成或计费到上限。

| 自动模式 | 默认输出额度 |
|---|---:|
| OpenAI Chat：未指定、none、low、medium | 32,768 |
| OpenAI high、xhigh、max；Responses 推理请求 | 65,536 |
| OpenAI Responses none | 32,768 |
| DeepSeek 非思考 | 8,192 |
| DeepSeek 思考（含未指定档位） | 65,536 |
| DeepSeek max | 131,072 |
| 未识别的自定义模型 | 4,096 |

OpenAI 的默认值是本站策略；DeepSeek 参考官方 Chat 默认值。DeepSeek Chat 的显式 thinking 开关优先决定是否思考。固定路由档位继续禁止客户端覆盖。

允许上限不受用户 TPM 数值限制，但每次请求仍必须有足够的可用 TPM 和月额度。例如 TPM 50,000 的 Key 无法承载 65,536 的输出预算加输入，可由客户端指定 `max_output_tokens=32768`（Responses）或 `max_completion_tokens=32768`（Chat），或由管理员调整配额。配额不足返回 429，附本次预留组成。

## 配置和发布

迁移 `0003` 仅添加可空字段，并把现有路由旧上限回填为固定默认值，保证迁移本身保持原行为。随后通过独立配置脚本将官方供应商路由切换为上述新策略；不编辑用户、Key、授权、上游凭据或自定义供应商路由。

```sh
docker compose exec -T api python - < scripts/configure_output_budgets.py
docker compose exec -T api python - --apply < scripts/configure_output_budgets.py
```

脚本默认预览，重复执行无变更；正式应用将每条旧/新值写入管理员审计日志。两个模型目录创建脚本也使用官方允许上限和自动默认，仍保留已存在路由的管理员设置。

发布前备份数据库、源文件和旧 API/Nginx 镜像。代码回退时先按本次配置审计或发布前备份中的路由值恢复 `max_output_tokens`，再回退 API 镜像，避免旧代码把放大的允许上限重新作为默认预留。可保留新增列，不必全库恢复；如需撤销迁移，应使用新镜像执行 `alembic downgrade 0002` 后再回退镜像。不要覆盖新的用量账本。
