# Token Station 阿里云轻量应用服务器部署指南

> 适用项目：`Token Station v1`
> 目标平台：阿里云轻量应用服务器（美国弗吉尼亚）
> 文档日期：2026-08-16

## 1. 当前服务器情况与部署结论

我已对你提供的阿里云控制台做了只读检查，确认：

- 地域：美国（弗吉尼亚），地域标识为 `us-east-1`。
- 当前有 1 台轻量应用服务器。
- 实例名称：`Docker-mfic`。
- 实例处于运行状态。
- 实例使用 Docker 应用镜像，控制台提供“应用详情”“防火墙”“命令助手”“磁盘”“监控”等页面。

因此，这台服务器适合直接采用本项目的 Docker Compose 方案，不需要重置系统，也不建议为了部署本项目而更换镜像。阿里云明确说明重置系统会清除系统盘数据；如果服务器已经承载其他内容，重置系统会造成数据丢失。[阿里云：重置系统或更换镜像](https://help.aliyun.com/zh/simple-application-server/user-guide/reset-a-simple-application-server)

控制台没有稳定返回规格正文，所以以下项目必须通过服务器预检确认，不能凭实例名称猜测：

- 操作系统和版本。
- CPU、内存、剩余磁盘。
- Docker Engine 和 Docker Compose 版本。
- 80、443 端口是否已被 Docker 示例应用或其他网站占用。
- 公网 IPv4 地址。

本项目最低建议：2 vCPU、4 GiB 内存、30 GiB 可用磁盘。2 vCPU、2 GiB 也可能启动，但 PostgreSQL、Redis、Python API、Nginx 和镜像构建会争用内存，不建议作为正式生产规格。阿里云当前轻量通用型规格中，`2 vCPU / 4 GiB / 50 GiB` 是更合适的起点。[阿里云：轻量应用服务器实例规格](https://help.aliyun.com/zh/simple-application-server/product-overview/instance-families/)

## 2. 最终部署结构

部署完成后，公网只接触 Nginx：

```text
用户 / OpenAI SDK
        |
        | HTTPS :443
        v
      Nginx
        |
        +---- /api/*  ---> FastAPI
        +---- /v1/*   ---> OpenAI 兼容代理
        +---- 静态文件 ---> React 控制台
                           |
                 +---------+---------+
                 |                   |
              PostgreSQL           Redis
              不开放公网           不开放公网
```

端口策略：

| 端口 | 来源 | 用途 | 是否公网开放 |
|---|---|---|---|
| 22/TCP | 你的固定公网 IP `/32` | SSH 管理 | 是，但只允许管理员 IP |
| 80/TCP | `0.0.0.0/0` | ACME 验证和 HTTPS 跳转 | 是 |
| 443/TCP | `0.0.0.0/0` | 控制台和模型 API | 是 |
| 5432/TCP | Docker 内网 | PostgreSQL | 否 |
| 6379/TCP | Docker 内网 | Redis | 否 |
| 8000/TCP | Docker 内网 | FastAPI | 否 |

阿里云轻量服务器的 Linux 防火墙通常预置 22、80、443，但仍要进入实例的“防火墙”页逐项确认。阿里云建议按需限制来源 IP，遵循最小授权原则。[阿里云：管理轻量服务器防火墙](https://help.aliyun.com/zh/simple-application-server/user-guide/manage-the-firewall-of-a-server)

## 3. 上线前必须准备的内容

请先准备：

1. 一个域名或子域名，例如 `token.example.com`。
2. 该域名 DNS 的修改权限。
3. 一个用于 Let’s Encrypt 通知的邮箱。
4. 阿里云服务器公网 IP。
5. SSH 登录凭证，推荐密钥对。
6. 管理员初始邮箱和强密码。
7. 上游 OpenAI 兼容服务的 HTTPS Base URL 和真实 API Key。

正式环境必须使用域名和 HTTPS。只使用公网 IP 时，可以检查服务器和容器，但不能完成本项目的正式登录验收，因为生产 Cookie 带有 `Secure` 属性，且 Nginx 在证书签发前会拒绝普通登录和模型调用。

## 4. 第一步：先给服务器做快照

在任何端口调整、文件上传或容器变更前：

1. 打开阿里云轻量应用服务器控制台。
2. 进入 `Docker-mfic`。
3. 打开“磁盘”。
4. 在系统盘操作中选择“创建快照”。
5. 名称建议使用 `before-token-station-20260816`。
6. 等待快照状态变为成功，再继续部署。

轻量服务器单实例最多可保留 3 个快照，快照可以用于误操作或攻击后的恢复。但快照会随实例到期释放而清除，因此不能替代项目自身的数据库备份。[阿里云：管理快照](https://help.aliyun.com/zh/simple-application-server/user-guide/manage-snapshots)

## 5. 第二步：确认公网 IP、登录方式和防火墙

### 5.1 获取公网 IP

在服务器列表或实例概览中复制“公网 IP”。阿里云官方文档也说明，实例卡片可以直接查看并复制公网 IP。[阿里云：查看服务器信息](https://help.aliyun.com/zh/simple-application-server/user-guide/view-lightweight-application-server-information)

本文后续用下面的占位符表示：

```text
<SERVER_IP>      服务器公网 IPv4
<DOMAIN>         例如 token.example.com
<ADMIN_IP>       你当前电脑的公网 IPv4
```

### 5.2 推荐配置 SSH 密钥

可以先用控制台中的“远程连接”进入 Workbench。服务器没有默认登录密码；首次采用密码方式时，需要先在控制台设置密码。长期管理建议创建并绑定 SSH 密钥对。[阿里云：远程连接 Linux 服务器](https://help.aliyun.com/zh/simple-application-server/user-guide/connect-to-linux-server-remotely)

macOS 使用密钥登录的示例：

```bash
chmod 400 /你的路径/token-station.pem
ssh -i /你的路径/token-station.pem root@<SERVER_IP>
```

不要通过聊天、邮件或网盘发送私钥文件。

### 5.3 调整轻量服务器防火墙

进入实例详情的“防火墙”页面，最终只保留本项目需要的公网规则：

| 应用 | 协议 | 端口 | 来源 IP | 备注 |
|---|---|---:|---|---|
| SSH | TCP | 22 | `<ADMIN_IP>/32` | 管理员 SSH |
| HTTP | TCP | 80 | `0.0.0.0/0` | HTTPS 跳转和证书验证 |
| HTTPS | TCP | 443 | `0.0.0.0/0` | Token Station |

不要添加 5432、6379、8000 的公网放行规则。

收紧 22 端口前，先保留当前 SSH 会话，并在新终端中确认使用密钥仍能登录，再关闭旧会话。如果你的家庭公网 IP 会动态变化，需在 IP 变更后及时更新这条规则，否则会将自己锁在服务器之外。

Let’s Encrypt 的 HTTP-01 验证必须从公网访问 TCP 80，证书签发后 80 端口继续用于跳转到 HTTPS。[Let’s Encrypt：HTTP-01 验证](https://letsencrypt.org/docs/challenge-types/)

## 6. 第三步：登录服务器并检查现有环境

登录服务器后执行：

```bash
uname -a
cat /etc/os-release
docker --version
docker compose version
docker ps --format 'table {{.Names}}\t{{.Image}}\t{{.Status}}\t{{.Ports}}'
df -h
free -h
sudo ss -lntp
```

重点检查：

- `docker compose version` 必须成功。应使用 Compose plugin，即命令是 `docker compose`，不是旧版 `docker-compose`。
- 可用内存建议至少 4 GiB。
- 当前目录所在磁盘建议至少剩余 30 GiB。
- 80、443 是否已经被其他进程或容器占用。

阿里云 Docker 应用镜像可以在实例的“应用详情”中查看 Docker 版本、状态和安装路径。[阿里云：使用 Docker 应用镜像](https://help.aliyun.com/zh/simple-application-server/use-cases/deploy-and-use-docker)

### 如果 80 或 443 已被占用

先识别占用者：

```bash
sudo ss -lntp | grep -E ':(80|443)[[:space:]]'
docker ps --format 'table {{.Names}}\t{{.Image}}\t{{.Ports}}'
```

不要直接执行批量停止或删除命令。Docker 应用镜像可能预装了一个演示 Nginx 容器，也可能是你已有的其他业务。确认容器名称和用途、完成快照后，再单独停止明确不需要的容器：

```bash
docker stop <明确确认不再使用的容器名>
```

如果现有网站仍需保留，则不要抢占 80/443，需要改为复用现有反向代理或换一台服务器。

### 如果 Docker Compose 不存在

优先在阿里云“应用详情”中确认 Docker 镜像安装是否完整。Ubuntu 22.04/24.04 可以按照 Docker 官方仓库安装 `docker-compose-plugin`；不要使用来源不明的一键脚本。[Docker：Ubuntu 安装 Docker Engine](https://docs.docker.com/engine/install/ubuntu/)、[Docker：安装 Compose plugin](https://docs.docker.com/compose/install/)

## 7. 第四步：把项目上传到服务器

本地项目路径是：

```text
/Users/markov/Desktop/token中转站
```

先在服务器创建目录：

```bash
sudo install -d -m 750 /opt/token-station
```

然后在你的 Mac 终端执行。以下命令应在本地执行，不是在服务器中执行：

```bash
rsync -avz --progress \
  --exclude '.env' \
  --exclude '.venv' \
  --exclude '.pytest_cache' \
  --exclude '.ruff_cache' \
  --exclude 'frontend/node_modules' \
  --exclude 'frontend/dist' \
  --exclude '*.db' \
  --exclude 'backups' \
  -e 'ssh -i /你的路径/token-station.pem' \
  '/Users/markov/Desktop/token中转站/' \
  root@<SERVER_IP>:/opt/token-station/
```

如果你使用密码登录，可以删除 `-e 'ssh -i ...'` 这一行。

上传后回到服务器：

```bash
cd /opt/token-station
chmod 755 scripts/*.sh deploy/nginx/entrypoint.sh
find . -maxdepth 2 -type f | sort | sed -n '1,80p'
```

确认至少存在：

```text
docker-compose.yml
Dockerfile
.env.example
app/
frontend/
alembic/
deploy/nginx/
scripts/
```

## 8. 第五步：运行项目预检

在服务器执行：

```bash
cd /opt/token-station
./scripts/preflight.sh
```

预检会检查：

- Docker、curl、OpenSSL。
- Docker Compose plugin。
- CPU 核数。
- 内存总量。
- 当前磁盘剩余空间。
- 80、443 端口占用。

只有依赖项全部为 `OK`，并且你已经处理所有 `WARN`，才继续。

建议把预检结果保存下来：

```bash
./scripts/preflight.sh | tee /root/token-station-preflight.txt
```

## 9. 第六步：配置域名 DNS

以 `token.example.com` 为例，在域名 DNS 控制台添加：

| 记录类型 | 主机记录 | 记录值 | TTL |
|---|---|---|---|
| A | `token` | `<SERVER_IP>` | 600 秒或默认值 |

如果使用根域名，则主机记录通常填写 `@`。A 记录用于把域名指向 IPv4 地址。[阿里云：配置网站 A 记录](https://help.aliyun.com/zh/dns/pubz-add-website-parsing)

等待解析生效后，在本地和服务器分别检查：

```bash
dig +short <DOMAIN>
```

没有 `dig` 时：

```bash
getent ahostsv4 <DOMAIN>
```

返回的 IPv4 必须与服务器公网 IP 完全一致。DNS 未生效前不要运行证书签发脚本。

## 10. 第七步：创建生产环境配置

在服务器执行：

```bash
cd /opt/token-station
umask 077
cp .env.example .env
chmod 600 .env
```

生成安全随机值：

```bash
openssl rand -hex 32
openssl rand -hex 32
openssl rand -hex 48
openssl rand -base64 32 | tr '+/' '-_'
```

四行输出依次用作：

1. `POSTGRES_PASSWORD`
2. `REDIS_PASSWORD`
3. `SECRET_KEY`
4. `TOKEN_ENCRYPTION_KEY`

PostgreSQL 和 Redis 密码使用十六进制，是为了避免密码放入数据库 URL 时需要额外 URL 编码。

使用 `nano .env` 或 `vi .env` 编辑，最终结构如下：

```dotenv
DOMAIN=<DOMAIN>
LETSENCRYPT_EMAIL=<你的证书通知邮箱>
TLS_ENABLED=false

POSTGRES_PASSWORD=<第一个 openssl rand -hex 32 的结果>
REDIS_PASSWORD=<第二个 openssl rand -hex 32 的结果>
SECRET_KEY=<openssl rand -hex 48 的结果>
TOKEN_ENCRYPTION_KEY=<URL-safe Base64 结果>
TOKEN_ENCRYPTION_KEY_VERSION=1

BOOTSTRAP_ADMIN_EMAIL=<管理员邮箱>
BOOTSTRAP_ADMIN_PASSWORD=<至少12位的强初始密码>
```

管理员密码要求：12–128 位，并在大小写字母、数字、符号四类中至少包含三类。例如可以采用密码管理器生成 20 位以上密码。不要直接使用文档中的示例文字。

保存后执行以下检查，它们只检查配置是否仍含占位符，不输出秘密：

```bash
if grep -q 'CHANGE_ME' .env; then
  echo 'ERROR: .env 仍包含 CHANGE_ME'
else
  echo 'OK: 所有占位符已替换'
fi

test "$(stat -c '%a' .env)" = '600' && echo 'OK: .env 权限为 600'
docker compose config --quiet
```

`TOKEN_ENCRYPTION_KEY` 用于解密数据库里的真实上游 Key。它必须离线备份到密码管理器；一旦丢失，已经保存的上游 Key 无法恢复。不要在项目更新时重新生成它。

## 11. 第八步：启动服务并签发 HTTPS

确保满足以下条件：

- DNS 已解析到当前公网 IP。
- 阿里云防火墙已开放 80/443。
- 80/443 没有被其他程序占用。
- `.env` 没有 `CHANGE_ME`。

执行：

```bash
cd /opt/token-station
./scripts/enable-tls.sh
```

脚本会自动：

1. 构建 React/Nginx 和 FastAPI 镜像。
2. 启动 PostgreSQL、Redis、API、Nginx。
3. 执行 Alembic 数据库迁移。
4. 先以仅允许 ACME 和存活检查的 HTTP 配置启动 Nginx。
5. 使用 Certbot webroot 完成 Let’s Encrypt HTTP-01 验证。
6. 把 `.env` 中的 `TLS_ENABLED` 改为 `true`。
7. 重建 Nginx，正式启用 HTTPS。

首次构建需要下载 Python、Node、PostgreSQL、Redis、Nginx 和 Certbot 镜像，耗时取决于公网带宽。不要因为几分钟没有结束就中断。

如果命令失败，先不要反复重跑，执行：

```bash
docker compose ps -a
docker compose logs --tail=200 api nginx postgres redis
```

根据日志处理第 16 节中的故障。

## 12. 第九步：部署后技术验收

### 12.1 容器状态

```bash
cd /opt/token-station
docker compose ps
```

预期：

- `postgres`：healthy
- `redis`：healthy
- `api`：healthy
- `nginx`：running
- 只有 `nginx` 显示宿主机 80/443 端口映射

### 12.2 健康检查

```bash
curl -fsS https://<DOMAIN>/health/live
curl -fsS https://<DOMAIN>/health/ready
```

预期：

```json
{"status":"ok"}
```

```json
{"status":"ok","checks":{"database":true,"redis":true,"migrations":true}}
```

### 12.3 HTTP 强制跳转 HTTPS

```bash
curl -I http://<DOMAIN>/
```

预期为 `301`，`Location` 指向 `https://<DOMAIN>/`。

### 12.4 证书检查

```bash
echo | openssl s_client -connect <DOMAIN>:443 -servername <DOMAIN> 2>/dev/null \
  | openssl x509 -noout -subject -issuer -dates
```

检查域名、签发者和到期时间。

### 12.5 生产调试文档关闭

```bash
curl -sS -o /dev/null -w '%{http_code}\n' https://<DOMAIN>/docs
```

预期返回 `404`。

### 12.6 数据库和 Redis 未暴露公网

```bash
docker compose ps
sudo ss -lntp
```

宿主机不应监听 `0.0.0.0:5432`、`0.0.0.0:6379` 或 `0.0.0.0:8000`。

## 13. 第十步：完成首次业务配置

浏览器打开：

```text
https://<DOMAIN>/
```

按顺序操作：

1. 使用 `.env` 中的 `BOOTSTRAP_ADMIN_EMAIL` 和初始密码登录。
2. 系统会强制修改初始密码，立即换成密码管理器保存的新密码。
3. 进入“上游”，新增国内 OpenAI 兼容服务：
   - 名称：便于识别的名称。
   - Base URL：上游官方提供的 HTTPS `/v1` 根地址。
   - 真实 API Key：只在服务器端加密保存。
   - 超时：通常先用 120 秒。
   - 如果上游明确支持流式最终 usage，再启用“流式 usage”。
4. 点击“测试连接”。
5. 进入“模型”，建立公开模型别名到上游真实模型名的映射。
6. 进入“用户”，创建第一个普通用户：
   - 有限的月 Token 额度。
   - 每把 Key 的 RPM 上限。
   - 每把 Key 的 TPM 上限。
   - 允许调用的公开模型。
7. 普通用户首次登录并修改临时密码。
8. 普通用户创建访问 Key，并立即保存唯一一次显示的明文。

## 14. 第十一步：使用 OpenAI SDK 验收真实调用

先验证模型列表：

```bash
export TOKEN_STATION_KEY='ts_sk_这里替换为用户Key'

curl -fsS https://<DOMAIN>/v1/models \
  -H "Authorization: Bearer $TOKEN_STATION_KEY"
```

验证非流式调用：

```bash
curl -fsS https://<DOMAIN>/v1/chat/completions \
  -H "Authorization: Bearer $TOKEN_STATION_KEY" \
  -H 'Content-Type: application/json' \
  -d '{
    "model": "管理员配置的公开模型名",
    "messages": [{"role": "user", "content": "请只回复：部署成功"}],
    "max_tokens": 32
  }'
```

验证流式调用：

```bash
curl -N https://<DOMAIN>/v1/chat/completions \
  -H "Authorization: Bearer $TOKEN_STATION_KEY" \
  -H 'Content-Type: application/json' \
  -d '{
    "model": "管理员配置的公开模型名",
    "messages": [{"role": "user", "content": "从1数到5"}],
    "stream": true,
    "max_tokens": 64
  }'
```

Python SDK：

```python
from openai import OpenAI

client = OpenAI(
    api_key="ts_sk_你的用户Key",
    base_url="https://<DOMAIN>/v1",
)

response = client.chat.completions.create(
    model="管理员配置的公开模型名",
    messages=[{"role": "user", "content": "你好"}],
)
print(response.choices[0].message.content)
```

调用成功后，在用户控制台和管理员调用日志中检查 Token、状态码、耗时和请求 ID。日志中不应出现提示词、回答或真实上游 Key。

## 15. 第十二步：配置备份、日志归档和证书续期

### 15.1 立即做第一次数据库备份

```bash
cd /opt/token-station
./scripts/backup.sh
ls -lh backups/
```

备份文件权限应为 `600`。项目会保留最近 7 天本地备份。生产环境还应把备份复制到独立权限保护的 OSS Bucket；服务器本机磁盘损坏时，本机备份无法救援。

### 15.2 先手工测试三个维护任务

```bash
./scripts/backup.sh
./scripts/retention.sh
./scripts/renew-tls.sh
```

全部成功后再配置 cron：

```bash
sudo crontab -e
```

加入：

```cron
12 2 * * * cd /opt/token-station && ./scripts/backup.sh >> /var/log/token-station-backup.log 2>&1
42 2 * * * cd /opt/token-station && ./scripts/retention.sh >> /var/log/token-station-retention.log 2>&1
17 3 * * * cd /opt/token-station && ./scripts/renew-tls.sh >> /var/log/token-station-certbot.log 2>&1
```

时间使用服务器本地时区。可以执行 `timedatectl` 确认；维护任务不依赖必须是北京时间。

### 15.3 测试备份可恢复性

恢复会替换数据库，只应在维护窗口或一台临时验收机上执行：

```bash
CONFIRM_RESTORE=yes ./scripts/restore.sh backups/token-station-YYYYMMDDTHHMMSSZ.sql.gz
```

恢复脚本会停止 API 和 Nginx、重建 `token_station` 数据库、导入备份，再重新启动服务。

## 16. 常见故障处理

### 16.1 `preflight` 提示 80 或 443 已占用

```bash
sudo ss -lntp | grep -E ':(80|443)[[:space:]]'
docker ps --format 'table {{.Names}}\t{{.Image}}\t{{.Ports}}'
```

只停止已经确认无用的具体服务。不要执行不带明确目标的批量删除命令。

### 16.2 Certbot 签发失败

依次检查：

```bash
dig +short <DOMAIN>
curl -v http://<DOMAIN>/health/live
docker compose logs --tail=200 nginx certbot
```

常见原因：

- DNS 仍指向旧 IP。
- 80 端口没有对公网开放。
- 80 端口被另一套 Nginx 或容器占用。
- 域名经过了错误配置的代理或 CDN。
- DNS 刚修改，尚未传播。

### 16.3 API 容器 unhealthy

```bash
docker compose ps -a
docker compose logs --tail=300 api postgres redis
```

重点看：

- `.env` 是否仍有 `CHANGE_ME`。
- `TOKEN_ENCRYPTION_KEY` 解码后是否正好 32 字节。
- PostgreSQL 或 Redis 密码是否被错误修改。
- Alembic 迁移是否成功。
- 磁盘是否已满。

### 16.4 页面能打开但登录后仍回到登录页

确认访问地址是 `https://`，不是服务器 IP 或 `http://`。生产 Session Cookie 带有 `Secure` 和严格 SameSite 属性。

### 16.5 模型调用返回 502

检查：

- Provider Base URL 是否是公网 HTTPS 地址。
- Base URL 是否已经包含上游要求的 `/v1` 根路径。
- 上游 Key 是否有效。
- 上游是否允许当前美国服务器 IP 访问。
- 上游服务条款是否允许中转使用。

服务会拒绝回环、私网、链路本地地址作为上游，以防 SSRF。

### 16.6 模型调用返回 429

429 可能来自：

- 单 Key RPM 用完。
- 单 Key TPM 预留不足。
- 账号月 Token 额度不足。
- 上游自身限流。

管理员先在控制台检查账号额度和 Key 上限，再结合调用日志的错误类型判断。

### 16.7 镜像构建时内存不足

先查看：

```bash
free -h
docker stats --no-stream
dmesg -T | grep -i -E 'out of memory|killed process' | tail -n 20
```

如果实例只有 2 GiB 内存，建议升级到至少 4 GiB，而不是长期依赖 swap。阿里云建议升级前创建快照。[阿里云：升级轻量服务器配置](https://help.aliyun.com/zh/simple-application-server/product-overview/upgrade-description)

## 17. 日常运维命令

```bash
cd /opt/token-station

# 查看状态
docker compose ps

# 查看最近日志
docker compose logs --tail=200 api nginx postgres redis

# 持续查看 API 和 Nginx 日志
docker compose logs -f --tail=100 api nginx

# 查看资源占用
docker stats

# 健康检查
curl -fsS https://<DOMAIN>/health/ready

# 手工备份
./scripts/backup.sh

# 安全重启业务容器
docker compose restart api nginx
```

不要执行：

```text
docker compose down -v
```

`-v` 会删除 PostgreSQL、Redis 和证书卷，属于数据破坏操作。

## 18. 项目更新流程

更新前：

```bash
cd /opt/token-station
./scripts/backup.sh
docker compose ps
```

建议同时创建一份阿里云快照。然后从 Mac 再次执行第 7 节的 `rsync` 命令。该命令没有 `--delete`，不会删除服务器的 `.env` 和 `backups/`。

服务器上执行：

```bash
cd /opt/token-station
docker compose config --quiet
docker compose up -d --build
docker compose ps
curl -fsS https://<DOMAIN>/health/ready
```

不要把 `.env` 从本地覆盖到服务器，也不要重新生成 `TOKEN_ENCRYPTION_KEY`。

## 19. 回滚方案

### 19.1 应用代码回滚

每次更新前可以保存不含秘密和备份的源码包：

```bash
cd /opt/token-station
tar \
  --exclude='.env' \
  --exclude='backups' \
  --exclude='.git' \
  -czf /root/token-station-source-before-update.tar.gz .
```

如果新版本仅代码或镜像构建失败，可以恢复旧源码，再执行：

```bash
cd /opt/token-station
tar -xzf /root/token-station-source-before-update.tar.gz
docker compose up -d --build
curl -fsS https://<DOMAIN>/health/ready
```

### 19.2 数据库回滚

数据库迁移或数据异常时，使用更新前的 `pg_dump`：

```bash
cd /opt/token-station
CONFIRM_RESTORE=yes ./scripts/restore.sh backups/<明确选择的备份文件>.sql.gz
```

### 19.3 整机回滚

只有代码和数据库备份都无法恢复时，才考虑阿里云快照回滚。快照回滚是不可逆操作，会丢失快照之后的服务器数据，执行前应再创建一份当前状态快照。[阿里云：使用快照回滚磁盘](https://help.aliyun.com/zh/simple-application-server/user-guide/manage-snapshots)

## 20. 合规与地域说明

当前实例位于美国弗吉尼亚，不属于中国内地。阿里云说明，网站部署在中国内地服务器时需要 ICP 备案，非中国内地服务器不要求以 ICP 备案作为上线前置条件；但如果向中国内地用户提供服务，仍应自行确认公安备案、隐私、数据跨境和上游服务条款等要求。[阿里云：ICP 备案适用范围](https://help.aliyun.com/en/icp-filing/basic-icp-service/product-overview/icp-filing-application-for-enterprises-outside-the-chinese-mainland)

Token Station 不应被用于绕过模型服务商限制。管理员必须确认上游协议允许代理、转售或多人共享调用能力。
